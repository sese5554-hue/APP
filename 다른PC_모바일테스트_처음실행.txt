근차 — 다른 PC에서 처음 실행하고 Android 휴대폰으로 테스트하기
작성일: 2026-11-14

가장 빠른 순서
1. 다른 Windows PC에 releases 폴더의 설치 EXE를 복사해 설치한다.
2. PC와 Android 휴대폰을 같은 Wi-Fi/공유기에 연결한다.
3. PC 시작 메뉴에서 Geuncha Mobile Test를 실행한다.
4. 실행 창의 SCREEN TEST URL을 휴대폰 Chrome에서 연다.
5. 게스트·호스트 버튼으로 화면을 테스트한다.
6. 앱으로 설치하려면 같은 페이지에서 APK를 내려받아 설치한다.
7. 앱 상단의 PC 연결 주소 설정에 새 PC의 주소를 넣는다.

AWS, 도메인, 외부 배포 서버는 필요하지 않다.
PC가 임시 서버 역할을 하므로 테스트 중에는 PC와 실행 창을 켜 두어야 한다.


1. PC 준비 — Windows 설치 EXE 사용 (권장)

[준비물]
- Windows 10 22H2 이상 또는 Windows 11, x64 호환 PC
- releases/Geuncha-Setup-0.1.0-win-x64.exe
- Android 휴대폰과 PC가 연결될 같은 공유기/Wi-Fi

[설치 및 실행]
1) 위 EXE 하나를 다른 PC에 복사하고 실행한다.
2) 설치 안내에 따라 설치한다.
   Node.js와 MariaDB는 포함되어 있으므로 따로 설치하지 않아도 된다.
   Microsoft Visual C++ 런타임 설치가 표시되면 설치를 진행한다.
3) 설치 완료 후 일반 Geuncha가 자동 실행됐다면 실행 창에서 Ctrl+C로
   종료한 다음, 시작 메뉴의 Geuncha Mobile Test를 실행한다.
   일반 PC 모드와 모바일 모드를 동시에 켜지 않는다.
4) 최초 실행의 DB 준비와 샘플 데이터 생성이 끝날 때까지 기다린다.
5) 실행 창에서 아래와 같은 주소를 찾는다.

   PHONE URL: http://192.168.0.10:3001
   SCREEN TEST URL: http://192.168.0.10:3001/mobile-test

   위 주소는 예시다. 반드시 새 PC 실행 창에 실제로 표시된 주소를 사용한다.
   사용 중인 포트에 따라 3001이 아닌 다른 숫자가 나올 수 있다.
6) Windows 방화벽의 네트워크 접근 허용 창이 나오면, 사용 중인
   신뢰할 수 있는 사설 네트워크에서 Node.js 접근을 허용한다.
7) 실행 창을 닫지 않고 아래 Android 휴대폰 작업을 진행한다.

설치 폴더의 Geuncha-Mobile.cmd로도 같은 모바일 테스트를 실행할 수 있다.
설치 폴더의 기본 위치는 현재 사용자 LocalAppData/Programs/Geuncha다.
새 PC에는 새 개발 DB가 생성된다. 기존 PC의 회원·예약 데이터가 자동 이전되지는 않는다.


2. PC 준비 — 설치 EXE 대신 프로젝트 폴더를 그대로 사용하는 경우

이 방법은 start-screen-test.cmd와 package.json이 있는 원본 프로젝트 폴더용이다.
Windows 설치 EXE로 설치했다면 이 항목을 건너뛴다.

1) 새 PC에 Node.js 22.12 이상을 설치한다.
2) 프로젝트 폴더를 새 PC의 쓰기 가능한 폴더에 둔다.
3) 최초 의존성·DB 도구 준비에 인터넷이 필요할 수 있다.
4) 프로젝트 최상위의 start-screen-test.cmd를 더블클릭한다.
   의존성 설치, 로컬 DB 준비, 마이그레이션과 개발 샘플 준비를 자동 진행한다.
5) SCREEN TEST URL이 나올 때까지 기다린다.

   소스 실행 예시: http://192.168.0.10:5173/mobile-test

6) PC와 휴대폰이 같은 공유기/Wi-Fi에 있는지 확인하고, 실행 창을 유지한다.

설치본의 Geuncha Mobile Test와 소스의 start-screen-test.cmd 중 한 방식만 사용한다.
휴대폰 주소는 5173이나 3001로 추측하지 말고 실행 창에 나온 값을 그대로 사용한다.


3. Android 휴대폰에서 할 일 — 브라우저로 먼저 확인

1) 휴대폰 설정 → Wi-Fi에서 PC와 같은 공유기에 연결한다.
   PC는 같은 공유기에 유선으로 연결되어 있어도 된다.
   게스트 Wi-Fi처럼 기기 간 통신이 차단된 네트워크는 피한다.
2) 휴대폰에서 Chrome을 연다.
3) PC 실행 창의 SCREEN TEST URL을 주소창에 그대로 입력한다.
   http:// 및 포트 번호와 /mobile-test까지 포함한다.
4) '휴대폰 화면 테스트' 페이지가 열리는지 확인한다.
5) '게스트 화면 테스트'를 누르면 테스트 계정으로 로그인한다.
6) 시작 페이지로 돌아와 '호스트 화면 테스트'도 확인한다.
   시작 페이지는 같은 SCREEN TEST URL로 다시 접속하면 된다.
7) 화면 바로가기 목록에서 00~51 화면을 선택할 수 있다.
   예약 상세·점검·정산 화면은 먼저 차량 선택과 예약 등 필요한 과정을 진행해야 한다.

수동 로그인 계정
- 게스트 아이디: guestdemo
- 호스트 아이디: hostdemo
- 공통 비밀번호: Geuncha123!

브라우저 화면이 열리지 않으면 APK 설치보다 먼저 7번의 접속 문제 해결을 확인한다.


4. Android 휴대폰에서 할 일 — APK 설치

1) 휴대폰 Chrome에서 위 테스트 페이지를 연다.
2) 'Android 테스트 APK 다운로드'를 누른다.
3) 다운로드가 끝나면 Geuncha-android-debug.apk를 연다.
4) 해당 출처의 앱 설치가 차단됐다고 표시되면 설정으로 이동한다.
   Chrome 또는 파일 앱에 대해 '이 출처 허용'을 켜고 설치 화면으로 돌아간다.
   메뉴 이름은 휴대폰 제조사와 Android 버전에 따라 다를 수 있다.
5) 앱 이름이 '근차'인지 확인하고 설치한다.
6) 설치가 끝나면 '열기'를 누르거나 홈 화면/앱 목록의 근차를 실행한다.

APK를 PC에서 USB나 파일 전송으로 옮겨 휴대폰의 파일 앱에서 설치해도 된다.
- 원본 프로젝트: releases/Geuncha-android-debug.apk
- Windows 설치본: 설치 폴더의 mobile/Geuncha-android-debug.apk

휴대폰에는 Java, Android Studio, Android SDK를 설치할 필요가 없다.
이 APK는 Android 7.0 이상을 대상으로 하는 개발 테스트용이다.


5. APK에서 새 PC 주소 설정하기

1) 근차 앱을 처음 열면 '테스트할 PC 연결' 창이 표시된다.
2) PC의 PHONE URL을 입력한다.

   예: http://192.168.0.10:3001

   SCREEN TEST URL을 그대로 입력해도 된다.
   예: http://192.168.0.10:3001/mobile-test

   반드시 현재 PC에 표시된 실제 주소를 사용한다.
   localhost, 127.0.0.1은 휴대폰 자신을 가리키므로 입력하지 않는다.
3) '연결'을 누르면 해당 PC의 모바일 테스트 페이지가 열린다.
4) PC, Wi-Fi 또는 IP 주소가 바뀌면 앱 상단의 'PC 연결 주소 설정'을 누른다.
5) 새 PC에 표시된 주소로 바꾸고 '연결'을 누른다.

주소만 바뀐 경우에는 APK를 다시 만들 필요가 없다.
휴대폰을 바꾸면 새 휴대폰에 APK를 설치하고 위 주소 설정을 다시 한다.
상단에 'PC 연결 주소 설정'이 없다면 예전 APK일 수 있으므로 최신 APK를 설치한다.


6. 앱에서 화면 테스트하기

1) 게스트 화면 테스트로 로그인한다.
2) 차량 목록 → 차량 상세 → 날짜·보험·결제수단 → 예약 요청 순서로 확인한다.
3) SCREEN TEST URL로 돌아와 호스트 화면 테스트로 로그인한다.
4) 차량 관리·예약 관리·수익 등 호스트 화면을 확인한다.
5) 사진 선택·촬영이 필요한 화면에서는 휴대폰에 나타나는 권한 요청을 확인한다.
   위치 기능을 눌렀을 때 권한 요청이 나오면 사용 목적에 맞춰 선택한다.

현재 PC의 HTTP 주소로 테스트할 때는 GPS·동네 인증이 제한될 수 있다.
화면 확인과 개발 계정 흐름을 먼저 테스트하고 위치 검증은 HTTPS 환경에서 확인한다.
실제 결제·본인 인증·보험 등 외부 운영 서비스는 아직 연결되지 않은 개발 버전이다.
테스트 중 변경한 내용은 연결된 PC의 개발 DB에 저장된다.


7. 휴대폰에서 접속이 안 될 때

[페이지가 열리지 않거나 연결 시간이 초과됨]
- PC의 실행 창이 켜져 있고 PHONE URL 또는 Ready가 표시됐는지 확인한다.
- PC와 휴대폰이 같은 공유기에 연결되어 있는지 확인한다.
- 휴대폰 주소의 IP와 포트가 PC 실행 창의 주소와 같은지 확인한다.
- http 주소를 입력했는데 https로 바뀌지 않았는지 확인한다.
- Windows 방화벽에서 해당 Node.js 실행 파일의 사설 네트워크 접근을 확인한다.
  방화벽 전체를 끄지 않는다.
- 회사/학교/게스트 Wi-Fi의 기기 간 통신 차단 여부를 확인한다.
- 먼저 휴대폰 Chrome에서 SCREEN TEST URL이 열리는지 확인한 뒤 앱 주소도 맞춘다.

[PC에서 포트가 사용 중이라고 표시됨]
- 기존 근차 실행 창을 Ctrl+C로 종료하고 하나의 실행 방식만 다시 시작한다.
- 다른 프로그램을 임의로 종료하지 않는다.

[APK 다운로드가 안 됨]
- 최신 Windows 설치본을 사용 중인지 확인한다.
- 프로젝트 폴더로 실행했다면 releases/Geuncha-android-debug.apk가 있는지 확인한다.
- PC에 있는 APK를 USB로 옮겨 설치해도 된다.

[로그인 또는 DB 준비 실패]
- PC 실행 창의 오류와 해당 실행 폴더의 .runtime/startup.log를 확인한다.
- 오류 확인을 위해 .env, DB 폴더, 업로드 폴더를 임의로 삭제하지 않는다.


8. 테스트 종료와 다음 실행

종료
- PC 실행 창에서 Ctrl+C를 누른다.
- 휴대폰 앱만 닫아도 PC 서버가 자동 종료되지는 않는다.

다음 실행
- Windows 설치본: 시작 메뉴 → Geuncha Mobile Test
- 원본 프로젝트: start-screen-test.cmd
- 실행 창의 현재 주소를 확인한 뒤 휴대폰으로 접속한다.
- PC 주소가 달라졌다면 근차 앱 상단의 PC 연결 주소 설정만 바꾼다.

참고 설정 파일
- android/test-settings.json: 프로젝트에서 Android 앱 빌드 시 기본 서버 설정
- ios/test-settings.json: 프로젝트에서 iOS 앱 빌드 시 기본 서버 설정
- 일반 화면 테스트와 Android 앱의 PC 주소 변경에는 이 파일을 수정할 필요가 없다.
- Windows 설치본의 위 파일들은 빌드 설정 참고용이며 실행 포트는 PC 실행 창이 기준이다.

iPhone 참고
- 같은 Wi-Fi에서 Safari로 SCREEN TEST URL을 열어 화면을 테스트할 수 있다.
- Safari 공유 → 홈 화면에 추가 → 이름을 근차로 확인 → 추가를 누른다.
  웹 앱으로 열기 선택이 보이면 켜 둔다. 이후 홈 화면의 근차 아이콘으로 실행한다.
- Windows PC만 있어도 이 홈 화면 추가 방식은 사용할 수 있다.
- PC 주소가 바뀌면 새 SCREEN TEST URL을 Safari에서 열고 아이콘을 다시 추가한다.
- 홈 화면 아이콘으로 실행해도 PC 서버와 같은 Wi-Fi 연결은 계속 필요하다.
- Android APK는 iPhone에 설치할 수 없다.
- iOS 앱 설치본 제작에는 별도의 Mac·Xcode·Apple 서명이 필요하다.

향후 Mac에서 네이티브 iOS 앱을 빌드할 때
- 원본 프로젝트를 Mac에 옮기고 bash ios/open-ios.command를 실행한다.
- Xcode에서 개발 Team과 고유 Bundle Identifier를 설정하고 Debug로 iPhone에 실행한다.
- 앱 상단의 PC 연결 주소 설정으로 새 PC 주소를 저장·변경할 수 있도록 구현했다.
- 현재 Windows에서는 Swift 컴파일, IPA 생성, iPhone 실기기 검증을 수행하지 못했다.
