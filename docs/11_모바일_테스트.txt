휴대폰에서 근차 테스트하기

실제 휴대폰 브라우저
1. PC와 휴대폰을 같은 공유기/로컬 네트워크에 연결한다. PC는 유선 이더넷이어도 되고 휴대폰은 해당 공유기의 Wi-Fi에 연결하면 된다. 휴대폰 모바일 데이터만으로는 접속할 수 없다.
2. 기존 start.cmd 실행 창을 종료하고 start-mobile.cmd를 실행한다. 이미 같은 모바일 모드로 정상 실행 중이면 기존 앱을 재사용한다.
3. 콘솔의 PHONE URL을 휴대폰 Chrome/Safari에 입력한다. 예: http://192.168.1.10:5173. 이 IP는 예시이며 실제 주소는 PC의 네트워크에 따라 자동 선택된다. 휴대폰에서 127.0.0.1이나 localhost를 사용하지 않는다.
4. 게스트 guestdemo / 호스트 hostdemo / 공통 비밀번호 Geuncha123!로 개발 기능을 테스트한다. PC 실행 창을 유지한다.
5. Windows 방화벽 허용 창이 나타나면 같은 집/사무실 네트워크의 개인 네트워크 접근을 허용한다. 게스트 Wi-Fi의 기기간 격리, 다른 공유기, VPN 등으로 연결되지 않을 수 있다. 스크립트가 방화벽 규칙을 자동 변경하지는 않는다.

실행 모드와 포트
- start.cmd: PC의 http://127.0.0.1:5173 접속.
- start-mobile.cmd: 실제 사설 LAN IPv4에만 웹 서버를 바인딩. API는 127.0.0.1에 두고 /api 프록시로 연결, MariaDB도 PC 내부 접속 유지.
- 모바일 모드의 Origin만 서버에서 허용한다. CORS/allowedHosts를 전체 허용하는 방식으로 바꾸지 않는다. .env는 덮어쓰지 않고 자식 프로세스 환경만 설정한다.
- 여러 네트워크 어댑터가 있으면 start-mobile.cmd --lan-ip 192.168.1.10처럼 PC에 실제 할당된 사설 IP를 지정할 수 있다. 해당 IP로 Wi-Fi/이더넷이 연결되어 있어야 한다.
- IP가 바뀌면 실행 창을 종료하고 다시 실행해 새 PHONE URL을 확인한다. 오류는 .runtime/startup.log에 기록된다.

위치·사진 테스트의 범위
- 일반 LAN HTTP 접속에서는 휴대폰 브라우저의 GPS 위치 확인이 제한된다. 새 가입자의 동네 인증까지 실제 기기에서 확인하려면 신뢰되는 HTTPS 테스트 환경이 필요하다. 현재 테스트 계정은 개발 인증이 저장되어 있어 검색·예약·채팅·사진 파일 선택·반납 흐름을 확인할 수 있다.
- 현재 사진 입력은 파일 선택/카메라 capture 힌트 기반이며 네이티브 앱 카메라가 아니다. 실제 카메라 선택 UI는 기기/브라우저별로 확인해야 한다.
- GPS secure context 공식 참고: https://developer.mozilla.org/en-US/docs/Web/API/Geolocation_API
- LAN 바인딩 공식 참고: https://vite.dev/config/server-options.html#server-host

PC에서 모바일 화면만 빠르게 확인
Chrome에서 앱을 열고 F12 → Ctrl+Shift+M → 화면 크기 390×844 등을 선택한다. 이는 화면 크기/터치 모의 테스트이며 실제 휴대폰 검증을 대체하지 않는다.

수행한 검증
Windows PC의 실제 사설 LAN 주소에서 웹 서버 시작, Chrome 390×844+모바일/터치 에뮬레이션 로그인 및 세션 유지, 다른 Origin의 변경 요청 403, 가로 넘침/페이지 오류 없음 확인. 실제 휴대폰 기기와 해당 Wi-Fi 방화벽 경로는 사용자가 확인해야 한다. 공유기 포트포워딩/AWS 배포는 하지 않았다.
