기록 원칙: 새 오류는 번호를 추가하고 증상·원인·수정·검증·남은 확인을 기록한다.

[ERR-001] 모바일 차량 예약 선택 후 다음 화면 표시 실패
중요도: 치명적 / 상태: 코드 수정 및 브라우저 검증 완료, 실기기 재설치 확인 필요
접수: 모바일 앱으로 차량 예약 선택 시 다음 페이지가 표시되지 않음.
환경: Android WebView에서 PC의 HTTP LAN IP 서버에 접속하는 테스트 구성.

원인과 근거
- Guest.tsx의 Reservation 생성 시 crypto.randomUUID()를 무조건 실행했다.
- 이 API는 보안 컨텍스트에 한정된다. PC localhost에서는 동작하지만
  휴대폰이 접속하는 http://PC-IP 주소에서는 제공되지 않는다.
- 실제 http://192.168.55.3:5173 브라우저 검사 결과:
  isSecureContext=false, typeof crypto.randomUUID=undefined.
  기존 호출의 오류: crypto.randomUUID is not a function.
- 화면 생성 중 예외가 발생해 예약 날짜 화면을 표시하지 못하는 경로를 확인했다.
  사용자의 휴대폰 원본 로그를 확보한 것은 아니며 같은 접속 환경에서 원인을 재현했다.

해결 과정
1. 예약 화면 진입 시 실행되는 코드와 LAN 접속 구성을 추적했다.
2. requestKey.ts에 공통 createRequestKey 함수를 추가했다.
3. randomUUID가 있으면 사용하고, 없으면 HTTP에서도 제공되는 getRandomValues로
   UUID v4 형식의 난수 키를 생성한다. 예약 중복 제출 방지 키의 역할을 유지한다.
4. 예약·채팅·신고에서 직접 호출하던 다섯 곳을 공통 함수로 교체했다.
5. 브라우저 E2E에서 randomUUID를 제거하여 해당 환경이 계속 검증되게 했다.

검증 결과
- npm run check: 타입 검사, 단위 테스트 18개, 제품 빌드 통과.
- npm run test:integration: 인증·예약 동시성·결제·호스트·채팅 등 4개 통과.
- npm run test:e2e: 2개 통과. 예약 요청→호스트 승인→개발 결제→취소 및
  00~51번 화면의 런타임 오류·가로 넘침 검사 통과.
- 실제 LAN IP에서 로그인→차량 상세→날짜 선택하고 예약하기→14번 화면 이동 확인.
  페이지 실행 오류 0건, 가로 넘침 없음, 다른 Origin 요청은 403 거부 확인.
- 첫 E2E 실행은 로컬 MariaDB가 꺼져 ECONNREFUSED로 시작 실패했다.
  기존 데이터를 유지하며 DB를 실행한 뒤 재검증하여 통과했다.

3. 상단 설정 버튼에서 실행 창의 PHONE URL 또는 SCREEN TEST URL을 입력한다.
   이번 실행 주소: http://192.168.55.3:5173 (네트워크가 바뀌면 실행 창 주소 사용).

실물 휴대폰 터치 및 Android 네이티브 UI 육안 검증은 이 PC에서 수행하지 않았다.
기존 자동 테스트 범위 밖의 모든 오류가 없다고 보장하는 결과는 아니다.

[ERR-004] 채팅 연속 전송 시 화면 중단 / 2026-11-15 추가 접수
중요도: 치명적 / 상태: 수정 및 연속 전송 회귀 검증 완료
증상: 메시지를 연속 전송하면 채팅 화면이 멈추거나 사라짐.
재현: 기존 코드에서 전송 후 메시지 표시까지는 성공하지만 버튼이 사라졌다.
  브라우저 추적에 React 정리 단계 TypeError: l is not a function 기록.
원인: 메시지 수가 바뀔 때 실행하는 useEffect가 scrollIntoView의 반환값을
  그대로 반환했다. 이번 PC Chrome에서 실제 반환값은 Promise 객체였다.
  React는 effect 반환값을 정리 함수로 취급하므로 다음 갱신/화면 이탈에서
  Promise를 함수로 실행하려다 화면 전체가 중단되었다.
수정: effect 본문을 블록으로 바꿔 스크롤만 실행하고 반환하지 않도록 했다.
  같은 코드 패턴의 추가 사용 여부도 검색했다.
회귀 검사: 예약 생성 후 서로 다른 메시지 3개를 연속 전송하고 각 메시지 표시와
  전송 버튼 재활성화, 예약 화면으로 이동까지 확인하도록 E2E를 확장했다.

[ERR-005] 실행 오류 발생 시 빈 화면이 유지됨
중요도: 높음 / 상태: 복구 처리 추가
원인: 앱 최상위에 React 오류 경계와 전역 오류 복구 처리가 없었다.
수정: 렌더링 오류, 처리되지 않은 실행 오류 및 Promise 거부를 감지하면
  '오류가 발생했습니다. 첫 번째 화면으로 돌아갑니다.' 안내를 표시한다.
  2초 후 /screens/00 첫 화면으로 전체 이동하며 이전 예약 검색값을 제거한다.
  첫 화면에는 오류로 복귀했다는 안내를 다시 표시한다.
  복귀한 첫 화면 자체가 계속 실패하는 경우 무한 새로고침을 방지한다.
- 일반 입력 검증/서버 거부처럼 이미 화면에서 처리하는 오류는 기존 안내를 사용한다.
- API 요청과 응답 본문 읽기는 20초 제한 후 중단하고 오류 복귀를 시작한다.
  시간 초과가 서버 작업 취소를 보장하지 않으므로 재시도 전에 예약/채팅 목록을 확인한다.
- 브라우저/OS 자체 정지나 JS 스레드가 완전히 멎는 상황에서는 앱 코드도 실행되지
  않으므로 즉시 메시지 표시나 자동 복귀를 보장할 수 없다.
- 실제 휴대폰 터치 및 OS 강제 정지 검증은 수행하지 않았다.

[ERR-007] 인증 완료를 요구하지만 로그인 후 인증 위치를 찾기 어려움 / 2026-11-15
중요도: 예약 진행 방해 / 상태: 인증 진입 경로 추가
접수: '본인·동네·면허 인증을 모두 완료해 주세요.' 오류 뒤 인증 메뉴를 찾을 수 없음.
원인: 본인 인증은 가입 단계에만 존재했고 마이페이지에 직접 진입 메뉴가 없었다.
  동네 인증은 개인정보 수정 내부, 면허는 운전면허 관리 안에 있어 세 인증을 한눈에
  확인하거나 예약 화면에서 이동하기 어려웠다.
수정 내역
- VerificationStatus.tsx: 서버 /me/verifications를 조회하여 세 인증 상태와 바로가기 표시.
  성공 여부와 만료 시각을 함께 검사하고 개발 인증은 개발 완료로 구분한다.

- Guest.tsx: 예약 요청 버튼 위에도 세 인증 바로가기 표시.
- Auth.tsx: 예약에서 인증을 시작하면 면허 단계 완료 후 기존 차량·일정을 유지한 채

제한: 현재 PC HTTP IP로 접속한 휴대폰에서는 GPS 제한으로 동네 인증이 불가능할 수 있다.

  첫 E2E는 DB 미실행으로 시작 실패했으며 기존 데이터를 유지해 DB 실행 후 전체 통과했다.

[개선-008] 마이페이지의 완료된 인증 메뉴 숨김 / 2026-11-15
요청: 인증을 완료할 때마다 해당 인증 메뉴를 제거한다.
변경: VerificationStatus에 hideCompleted 옵션을 추가하고 게스트·호스트 마이페이지에 적용.
  서버 인증 기록의 성공 상태와 유효기간을 확인하여 완료 항목만 숨긴다.
  세 가지 모두 유효하게 완료되면 '예약을 위한 인증' 카드 전체를 숨긴다.
  실패·미완료·만료된 인증은 다시 표시하여 재인증할 수 있도록 한다.
  화면에서 메뉴만 숨기며 서버 인증 기록은 삭제하지 않는다.
  예약 화면의 인증 상태 표시는 기존대로 유지하고 면허 관리 메뉴도 유지한다.
검증: 타입 검사 통과. 마이페이지 E2E에 0~3개 순차 완료, 전체 카드 숨김,
  만료된 동네 인증만 재표시하는 검사를 추가했다.

[ERR-009] 위치 권한 허용 후 동네 인증에서 입력 오류 표시 / 2026-11-15
중요도: 인증 진행 방해 / 상태: 검증 조건 및 안내 수정
접수: 입력란이 없는 동네 인증에서 '입력 내용을 확인해 주세요.'가 표시됨.
확인한 원인: 서버가 기기에서 자동 전달된 위치 정보를 일반 입력 검증으로 처리했다.
  accuracy가 0이면 positive 검사에 실패하고, 10000m 초과이면 max 검사에 실패하여
  같은 일반 입력 오류가 발생했다. 사용자의 기기 원본 요청값은 수집하지 않았으므로
  실제 실패 필드가 어느 쪽인지는 단정하지 않는다.
수정 내역
- auth/routes.ts: 정확도 0을 포함한 음이 아닌 수를 허용한다.
- 잘못된 좌표/시간 형식은 INVALID_POSITION으로 위치 정보를 다시 받으라는 안내 제공.
- 오차 10000m 초과 제한은 유지하되 INACCURATE_POSITION으로 정확한 위치 사용 및
  창가·실외 재시도 안내를 제공한다. 음수 정확도와 범위 밖 좌표는 계속 거부한다.
- 오래된 위치/기기 시각 차이는 STALE_POSITION으로 날짜·시간 자동 설정 안내를 제공한다.
- Auth.tsx: 재시도 시작 시 이전 오류를 지우고 위치 확인 중 상태를 표시한다.
  권한 거부·기기 위치 수신 실패·15초 GPS 시간 초과의 안내를 구분한다.
- 통합 검사: 정확도 0 정상 처리, 음수 정확도·범위 밖 위도 거부, 큰 오차와 오래된
  위치의 오류 코드 구분 검사를 추가했다.
- 브라우저 검사: 위치 권한 허용 후 오차 20000m 안내를 보고 정확도 0으로 재시도하여
  면허 화면으로 이동하고 서버의 동네 인증 완료 기록을 확인하는 검사를 추가했다.
한계: 실제 휴대폰 GPS 원본값으로 재현한 것은 아니며 브라우저 위치 모의값을 사용한다.
  HTTP 보안 컨텍스트 제한 및 개발 공급자의 신림동 예시 지역 판정은 그대로다.
검증 결과: 타입 검사·통합 4개·동네 관련 브라우저 2개·문서 검사 통과.
  브라우저 검증 전 DB 미실행으로 시작 실패하여 DB 실행 후 재검증했다.
  DB 준비 중 마이그레이션 명령에서 Node ENOMEM이 발생했으며 기존 DB 스키마로
  브라우저 검증을 수행했다. 신규 DB 스키마 변경은 없다.

[ERR-010] 사는 동네를 직접 입력·검색·선택할 수 없음 / 2026-11-15
접수: 사용자는 GPS 오류 수정을 요청한 것이 아니라 거주 동네를 직접 검색하여
  선택하는 기능이 없다고 설명했다. 앞선 대응은 요구를 잘못 해석했다.
원인: 동네 인증 화면은 GPS 버튼만 제공했고 검색 입력·주소 선택 기능이 없었다.
수정 내역
- NeighborhoodSearch.tsx: 동네/도로명/건물명 입력 → 주소 검색 → 결과 선택 →
  선택한 동네로 인증하는 화면 추가. 팝업 대신 페이지 내부 iframe 사용.
- 카카오 공식 우편번호 서비스 스크립트를 필요한 시점에 로드하고 검색어를 전달한다.
  연결 실패/15초 로딩 시간 초과 안내와 재시도를 지원하고 화면 이탈 후 갱신을 막는다.
- Auth.tsx: 검색 영역을 GPS 기능 앞에 배치했다. GPS는 별도 선택지로 유지한다.
- auth/routes.ts: method=address일 때 동네명과 10자리 법정동 코드를 검사한다.
  선택한 시도·시군구·동네 이름을 프로필과 인증 기록에 저장하고 상세주소는 받지 않는다.
  주소 선택 인증은 development 공급자에서만 허용하며 실제 거주지 인증으로 간주하지 않는다.
- app.ts: 운영 CSP에 카카오 스크립트 CDN과 우편번호 iframe 도메인을 명시했다.
검증

- 동네 관련 브라우저 테스트 3개 통과. 검색 서비스는 모의 스크립트로 연결해
  검색어 전달·선택·서버 저장·면허 화면 이동을 확인했다.

  열고 선택하여 '경기 성남시 분당구 백현동'이 앱에 표시되는 것을 확인했다.
