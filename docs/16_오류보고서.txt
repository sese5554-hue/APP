근차 오류보고서 (누적 기록)
작성일: 2026-11-15
기록 원칙: 새 오류는 번호를 추가하고 증상·원인·수정·검증·남은 확인을 기록한다.

[ERR-001] 모바일 차량 예약 선택 후 다음 화면 표시 실패
중요도: 치명적 / 상태: 코드 수정 및 브라우저 검증 완료, 실기기 재설치 확인 필요
접수: 모바일 앱으로 차량 예약 선택 시 다음 페이지가 표시되지 않음.
환경: Android WebView에서 PC의 HTTP LAN IP 서버에 접속하는 테스트 구성.

원인과 근거
- Guest.tsx의 Reservation 생성 시 crypto.randomUUID()를 무조건 실행했다.
- 이 API는 보안 컨텍스트에 한정된다. PC localhost에서는 동작하지만
  휴대폰이 접속하는 http://PC-IP 주소에서는 제공되지 않는다.
- 실제 http://192.168.55.3:5173 브라우저 검사 결과:
  isSecureContext=false, typeof crypto.randomUUID=undefined.
  기존 호출의 오류: crypto.randomUUID is not a function.
- 화면 생성 중 예외가 발생해 예약 날짜 화면을 표시하지 못하는 경로를 확인했다.
  사용자의 휴대폰 원본 로그를 확보한 것은 아니며 같은 접속 환경에서 원인을 재현했다.

해결 과정
1. 예약 화면 진입 시 실행되는 코드와 LAN 접속 구성을 추적했다.
2. requestKey.ts에 공통 createRequestKey 함수를 추가했다.
3. randomUUID가 있으면 사용하고, 없으면 HTTP에서도 제공되는 getRandomValues로
   UUID v4 형식의 난수 키를 생성한다. 예약 중복 제출 방지 키의 역할을 유지한다.
4. 예약·채팅·신고에서 직접 호출하던 다섯 곳을 공통 함수로 교체했다.
5. 브라우저 E2E에서 randomUUID를 제거하여 해당 환경이 계속 검증되게 했다.

검증 결과
- npm run check: 타입 검사, 단위 테스트 18개, 제품 빌드 통과.
- npm run test:integration: 인증·예약 동시성·결제·호스트·채팅 등 4개 통과.
- npm run test:e2e: 2개 통과. 예약 요청→호스트 승인→개발 결제→취소 및
  00~51번 화면의 런타임 오류·가로 넘침 검사 통과.
- 실제 LAN IP에서 로그인→차량 상세→날짜 선택하고 예약하기→14번 화면 이동 확인.
  페이지 실행 오류 0건, 가로 넘침 없음, 다른 Origin 요청은 403 거부 확인.
- 첫 E2E 실행은 로컬 MariaDB가 꺼져 ECONNREFUSED로 시작 실패했다.
  기존 데이터를 유지하며 DB를 실행한 뒤 재검증하여 통과했다.

[ERR-002] PC 연결 설정 버튼이 모바일 표시 공간을 차지함
중요도: 사용성 / 상태: 수정 및 Android 빌드 완료, 실기기 표시 확인 필요
원인: MainActivity가 웹 화면 위에 전체 너비 설정 버튼을 항상 표시했다.
수정: 기본값을 접힘으로 변경. 상단 우측 40dp 설정 버튼으로 펼치고
  빼기 버튼으로 다시 접는다. 웹 위에 겹치지 않는 별도 행을 유지한다.
  최초 실행의 주소 입력창 및 저장된 서버 주소 재사용은 유지한다.
검증: npm run mobile:apk의 Android Java 컴파일 및 assembleDebug 성공.
결과물: releases/Geuncha-android-debug.apk (Git 제외 로컬 설치 파일).

[ERR-003] HTTP 접속 시 채팅·신고 화면도 중단될 수 있음
중요도: 높음 / 상태: 동일 원인 수정 완료
원인: Shared.tsx의 메시지 키와 신고 중복 방지 키도 randomUUID를 직접 호출했다.
수정: ERR-001의 공통 함수를 사용하도록 변경했다.
검증: randomUUID 없는 환경에서 전체 52개 화면 검사 통과.

모바일 재테스트 방법과 남은 확인
1. PC에서 start-mobile.cmd 실행 후 같은 Wi-Fi로 연결한다.
2. 새 APK를 휴대폰에 업데이트 설치한다. 네이티브 설정 버튼 변경에는 재설치가 필요하다.
3. 상단 설정 버튼에서 실행 창의 PHONE URL 또는 SCREEN TEST URL을 입력한다.
   이번 실행 주소: http://192.168.55.3:5173 (네트워크가 바뀌면 실행 창 주소 사용).
4. guestdemo로 로그인 후 차량 상세에서 예약 날짜 선택 화면 진입을 확인한다.
5. 설정 펼치기/접기와 실제 기기의 상태 표시줄·키보드 표시를 확인한다.
실물 휴대폰 터치 및 Android 네이티브 UI 육안 검증은 이 PC에서 수행하지 않았다.
기존 자동 테스트 범위 밖의 모든 오류가 없다고 보장하는 결과는 아니다.
