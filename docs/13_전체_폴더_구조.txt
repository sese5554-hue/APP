근차(geuncha) 전체 폴더 구조와 파일 역할

1. 이 문서를 읽는 기준

프로젝트 최상위 폴더 geuncha/를 기준으로 설명한다.
소스코드·기획 문서·설치 제작 자료·실행 데이터를 함께 구분했다.
node_modules, .git, MariaDB 바이너리 등 외부 도구의 내부 파일은 묶어서 표시한다.
dist, node_modules, releases, .runtime은 설치·빌드·실행 후 생성되므로 새로 받은 Git 저장소에 없을 수 있다.
폴더 이름과 경로는 소스에서 참조하므로 임의로 바꾸면 실행이나 문서 생성이 실패할 수 있다.

3. 처음 찾을 파일

- 이 PC에서 소스를 실행: 루트 start.cmd.
- 휴대폰에서 테스트: PC에서 start-mobile.cmd 실행 후 표시된 주소를 같은 네트워크의 휴대폰 브라우저로 연다.
- 다른 Windows PC에 설치: releases/Geuncha-Setup-0.1.0-win-x64.exe를 전달해 실행한다.
- 설치본 실행: 설치 후 생성된 시작 메뉴 또는 바탕화면의 근차 바로가기를 사용한다.
- 화면별 구현 확인: docs/implementation/README.txt에서 번호를 고른다.
- 기능 요구사항 확인: docs/pages와 docs/01_PRD.txt를 읽는다.
- 실제 API 확인: docs/09_API_실행계약.txt와 apps/api/src/modules를 읽는다.
- 최신 작업·검증 기록 확인: docs/08_실제구현.txt를 읽는다.
- 이 폴더의 DB(마리아).txt는 실행 SQL이 아니다. 실제 테이블 생성 코드는 database/migrations다.

4. 코드가 연결되는 방향

브라우저
  -> apps/web/src/main.tsx에서 화면 선택
  -> pages의 컴포넌트가 api.ts로 /api 요청
  -> apps/api/src/app.ts에서 공통 보호 처리와 modules 라우터 연결
  -> 요청 검증·세션/권한 검사·업무 서비스
  -> database/db.ts를 통해 MariaDB 읽기/쓰기
  -> 결과를 웹 컴포넌트가 표시

packages/contracts는 입력 형식과 타입을 공유한다.
domain/pricing.ts는 서버에서 금액과 상태 전이를 계산한다.
providers는 외부 서비스 연결 경계이며 현재 개발 공급자와 미설정 상태를 구분한다.
이미지는 .runtime/uploads에, 이미지 소유자·용도·연결 정보는 DB에 저장한다.

5. 원본·자동 생성·실행 데이터를 구분하는 방법

직접 관리하는 소스:
  apps, packages, database/migrations, scripts, tests, installer, deploy,
  reference, 루트 설정 파일 및 실행 스크립트.

문서 생성 결과:
  README.md, docs/pages, 기능별 README TXT, docs/screen-manifest.json,
  docs/implementation은 문서 생성기를 다시 실행하면 갱신된다.
  화면별 실제 흐름 설명은 scripts/screen-implementation-data.mjs를 수정한다.
  생성 문서를 고칠 때는 해당 생성기/설명 데이터도 함께 수정한다.

수동 관리 문서:
  docs의 공통 설계·실행 안내·도구 기록·실제 구현 이력과 이 폴더 구조 문서.
  폴더나 주요 파일을 추가·변경하면 이 문서도 수정한다.

현재 PC에서 생성되는 자료:
  node_modules는 npm 설치, dist는 앱 빌드, releases는 설치파일 제작 결과다.
  .runtime에는 도구/캐시와 실제 사용자 데이터가 함께 있으므로 전체를 임시 폴더로 취급하면 안 된다.

6. 보존·공유 기준

- .runtime/mariadb-data와 .runtime/uploads는 현재 PC 데이터다. 경로 이동·삭제 시 기존 DB나 이미지가 사라질 수 있으므로 함께 보존한다.
- .env에는 비밀값이 있을 수 있다. Git이나 다른 사람에게 배포하는 설치 패키지에 넣지 않는다.
- 다른 PC용 설치파일은 이 PC의 기존 DB·업로드·.env를 복사하는 도구가 아니다. 새 PC는 별도 데이터를 준비한다.
- node_modules와 dist는 재설치/재빌드할 수 있는 결과물이지만, 삭제하면 다시 준비하기 전에는 실행이 실패할 수 있다.
- .git은 버전 관리 정보다. 프로젝트를 계속 관리하려면 보존한다.
- Git에 제외된 로컬 파일과 설치 EXE는 push만으로 다른 PC에 전달되지 않는다.
- deploy·Dockerfile·compose.yaml은 향후 운영 준비 자료다. AWS 배포나 Ubuntu 실기동을 완료했다는 뜻은 아니다.

7. 관리 명령과 사용 도구

문서 재생성: node scripts/generate-docs.mjs
문서 검사: node scripts/check-docs.mjs
앱 타입 검사: npm run typecheck
앱 빌드: npm run build
Windows 설치파일 제작: npm run installer:build

이번 구조 설명은 PowerShell 디렉터리 조회, rg 파일 목록, 실제 소스와 .gitignore를 대조해 작성했다.
새 패키지 설치나 앱 실행 데이터 변경은 하지 않았다.
