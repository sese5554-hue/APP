2. 화면별 구현 흐름
1) SharedPage가 Profile에 host=true를 전달해 호스트 마이페이지를 만든다. 프로필 값은 공통 AppContext 사용자 상태를 재사용한다.
2) 공통 개인정보 메뉴 외 수익 대시보드 36과 차량 관리 26 링크를 추가한다.
3) 게스트 전환은 guest 역할을 필요 시 추가하고 active_role을 바꾼 뒤 08로 이동한다. 로그아웃 처리도 37과 같은 폼을 사용한다.

6. SOLID·KISS·YAGNI 적용 구분
- SOLID / 책임 분리(SRP): Profile 컴포넌트는 화면 입력과 표시를 담당하고 apps/api/src/modules/auth/routes.ts는 해당 요청을 처리한다. UI에서 SQL을 실행하지 않고 필요한 검증·권한·상태 처리를 서버에 둔다.
- SOLID / 의존 방향: 결제 서비스는 PaymentProvider를 생성자로 받으며 개발·미설정 공급자를 구분한다. 이 화면이 외부 인증/분석을 호출할 때도 providers 경계를 사용한다. 공급자 호출이 없는 조회 화면에 불필요한 공급자 계층을 추가하지 않는다. 다섯 원칙의 공통 적용 설명은 ../04_SOLID_KISS_YAGNI.txt를 참조한다.
- KISS / 구현 단순화: 37·47은 Profile의 host 표시 옵션을 공유하고 같은 역할 전환·로그아웃 처리를 사용한다.
- YAGNI / 범위 제한: 이 화면의 현재 기능은 2절까지이며, 8절의 미연동·미구현 기능을 완료로 표시하지 않는다. 요구되지 않은 관리자·포인트·독립 마이크로서비스는 추가하지 않았다.
