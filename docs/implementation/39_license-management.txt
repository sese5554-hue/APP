- 실제 화면 컴포넌트: License (Shared.tsx).

- vehicle은 차량 ID, booking은 예약 ID, startsAt/endsAt는 UTC 기간, insuranceId는 선택 보험이다. 필요한 값은 이전 화면 선택으로 전달한다. 리소스 UUID를 문서의 예시 문자열로 대체하지 않는다.

2. 화면별 구현 흐름
1) 로그인 사용자의 kind=license 기록을 조회한다.
2) 서버가 JSON 메타데이터를 펼치고 expires_at이 지났으면 expired 상태를 반환한다. 화면은 마스킹 번호·종류·발급일·유효기간을 표시한다.
3) 기록이 없으면 빈 상태를 안내하고 입력/수정 버튼은 07로 이동한다. 이 조회 화면은 면허 원문을 저장하거나 수정하지 않는다.

3. 실제 백엔드 주요 API와 소스 위치
- GET /api/me/license

4. MariaDB 읽기·쓰기와 권한
- user_verifications: database/migrations/001_initial.sql:12
- 위 테이블은 조회·연결·검증에 참여하는 테이블이며 모두 수정한다는 뜻은 아니다. 실제 쓰기 및 상태 변경은 2절의 흐름을 따른다.

6. SOLID·KISS·YAGNI 적용 구분
- SOLID / 책임 분리(SRP): License 컴포넌트는 화면 입력과 표시를 담당하고 apps/api/src/modules/shared/account.ts는 해당 요청을 처리한다. UI에서 SQL을 실행하지 않고 필요한 검증·권한·상태 처리를 서버에 둔다.
- SOLID / 의존 방향: 결제 서비스는 PaymentProvider를 생성자로 받으며 개발·미설정 공급자를 구분한다. 이 화면이 외부 인증/분석을 호출할 때도 providers 경계를 사용한다. 공급자 호출이 없는 조회 화면에 불필요한 공급자 계층을 추가하지 않는다. 다섯 원칙의 공통 적용 설명은 ../04_SOLID_KISS_YAGNI.txt를 참조한다.
- KISS / 구현 단순화: License 컴포넌트에서 공통 api·Form·useData/Load를 필요한 곳에 재사용한다. 서버는 명시적 라우터와 SQL로 처리한다.
- YAGNI / 범위 제한: 이 화면의 현재 기능은 2절까지이며, 8절의 미연동·미구현 기능을 완료로 표시하지 않는다. 요구되지 않은 관리자·포인트·독립 마이크로서비스는 추가하지 않았다.
