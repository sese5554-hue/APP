순차 구현 계획과 기록 규칙
현재 기록은 계획이다. 실제 코드 작성 순서는 docs/07_구현기록.txt에 날짜와 파일을 남긴다.

준비 단계
P0: 원본/환경 확인, 폴더 구조, TypeScript strict 설정, workspace와 lockfile, .gitignore, .env.example.
P1: MariaDB migration runner/schema/seed, UTC·utf8mb4, 세션/인증/역할, 오류 계약, 보안 미들웨어.
P2: provider interface와 개발 adapter, 예약 상태·금액·잠금 처리, 업로드 권한 등 00~51이 공유할 기반.
기반 코드가 25번 호스트 차량 등록 API를 먼저 포함해도 화면 완료 순서는 아래 번호순으로 관리한다. 게스트 화면 검증에는 개발용 호스트·게스트·차량 시드를 사용한다.

화면 구현 순서
00~07: 약관, 비회원 탐색, 역할, 로그인, 가입, 본인, 동네, 면허.
08~13: 홈, 지도, 검색, 필터, 상세, 사양.
14~18: 기간, 요금 요약, 결제수단/요청, 요청·완료 표시, 예약 상세.
19~24: 채팅, 인수, 반납, 비교, 정산, 후기.
25~33: 호스트 홈, 차량 목록, 수정, 기본 정보, 종류, 상세, 사진, 분석, 운영 일정·요금.
34~36: 예약 목록, 요청 관리, 수익.
37~44: 마이페이지, 개인정보, 면허, 결제수단, 알림, 고객센터, 문의, 채팅 목록.
45~51: 게스트 예약, 결제수단 추가, 호스트 마이페이지, 보험, 세부 저장 완료, 추천 요금 이유, 게스트 평가.

의존성 처리
- 15~16의 보험 선택 서비스는 48 화면 전에 준비한다. 임시 보험료 하드코딩 대신 실제 계약 데이터를 조회한다.
- 16에서 사용하는 결제수단 API는 40/46 화면 전에 준비한다.
- 19의 저장/실시간 전송은 44 화면 전에 준비한다.
- 24의 후기 데이터는 51에서 재사용한다.
- 30의 저장 API는 49에서 재조회한다. 49는 실제 이동 흐름에서 30→49→31이다.
- 33의 추천 서비스는 50 화면 전에 준비하며 적용은 호스트가 명시적으로 선택한다.
