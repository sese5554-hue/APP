앱 최초 실행 파일 구현 프롬프트
현재 상태: start.cmd/start.sh, 공용 bootstrap, MariaDB Compose와 Windows portable 실행을 구현했다. Windows 최초 준비·재실행 및 데이터 보존을 검증했다. Ubuntu/Docker 실기동은 미검증이며 아래는 최초 요구사항을 보존한 명세다.
현재 제공한 문서검증.cmd는 문서를 생성/검사하며 앱을 실행하지 않는다.

실행 오류 보완: start.cmd는 준비 완료 후 기본 브라우저를 열며, 이미 정상 작동하는 근차는 중복 실행하지 않는다. 다른 프로그램/부분 실행 서버가 포트를 점유하면 명확히 안내하고 임의 종료하지 않는다. 단계·자식 프로세스 오류는 비밀번호를 제거해 .runtime/startup.log에 기록한다. 자동 검증 시 start.cmd --no-open으로 브라우저 열기만 생략할 수 있다.

구현할 파일
- Windows: start.cmd(더블클릭 진입), scripts/start.mjs(플랫폼 공용 준비·실행).
- Ubuntu: start.sh(동일한 공용 스크립트 호출), Dockerfile과 compose.yaml(MariaDB 및 선택적 앱 컨테이너).
- package.json: dev, build, start, typecheck, test, db:migrate, db:seed, check. 설치 버전과 lockfile 고정.
- .env.example: DB_HOST/PORT/NAME/USER/PASSWORD, 세션 설정, 공급자 mode, 프론트/서버 URL. 실제 비밀번호 없음.

최초 실행 동작
1. 실행 위치를 프로젝트 루트로 고정하고 Node.js 지원 버전 및 npm 실행 파일을 확인한다. Windows에서는 PowerShell npm.ps1 제한을 피하도록 npm.cmd를 호출한다. 전역 실행 정책을 변경하지 않는다.
2. 환경 파일이 없으면 개발용 값으로 생성하되 DB 비밀번호와 세션 비밀은 암호학적 난수로 만든다. 외부 비밀을 출력하지 않고 기존 .env는 덮어쓰지 않는다.
3. lockfile이 있는 경우 npm ci 또는 선택한 패키지 관리자의 동일 기능으로 설치한다. 실패하면 종료 코드를 전달하고 원인을 표시한다.
4. DB 실행 방식을 명시적으로 선택한다. 로컬 MariaDB 접속 또는 사용자가 선택한 Docker Compose. 자동으로 Docker를 설치하거나 기존 DB를 초기화하지 않는다.
5. DB 준비 상태를 제한 시간과 재시도로 확인한다. 타임아웃/포트 충돌/잘못된 DB 접속은 구체적으로 안내한다.
6. 버전 migration만 적용한다. 개발 seed는 명시한 개발 모드에서 한 번 생성하고 재실행 시 중복/삭제되지 않게 한다.
7. API와 프론트엔드 프로세스를 시작하고 healthcheck 후 로컬 URL을 표시한다. 기본은 로컬 인터페이스에 바인딩하고 외부 공개는 별도 설정한다.
8. Ctrl+C/오류 종료 시 자신이 실행한 자식 프로세스를 정리한다. 기존 DB 서비스나 관계없는 프로세스를 종료하지 않는다.
9. 두 번째 실행에서 포트 충돌을 알리고 데이터와 사용자 설정을 보존한다. 관리자 권한이나 시스템 설정 변경을 요구하지 않는 경로를 기본으로 한다.

Ubuntu 운영을 위한 준비만 수행
- Linux에서 파일명 대소문자·경로 구분자·실행 권한·줄바꿈을 확인한다. 셸 스크립트는 LF.
- Node.js 운영 빌드, 정적 프론트엔드 제공/리버스 프록시, MariaDB 비공개 접속, 환경 주입, HTTPS 세션 설정, 로그·상태 점검·정상 종료 방법을 문서화한다.
- UTC DB 연결/Asia/Seoul 표시, 업로드 저장소 경로/권한, DB/업로드 백업과 복구 절차를 문서화한다.
- AWS 리소스 생성·SSH 접속·DNS·인증서 설정·실제 배포는 현재 범위 밖이다.

검증 기준
새 폴더+빈 개발 DB → 최초 실행 성공 → 가입/시드 로그인 → DB에 차량/예약 유지 → 종료 → 재실행 후 동일 데이터 유지.
DB 미기동, Docker 없음, Node 버전 불일치, 환경 파일 누락, 공급자 미설정, 포트 충돌은 명확한 오류로 종료.
위 검증을 수행한 운영체제와 명령, 결과를 README 및 도구 기록에 남긴다. Windows 검증만으로 Ubuntu 실행을 검증했다고 기록하지 않는다.
