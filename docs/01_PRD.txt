근차 전체 PRD
상태: 구현을 위한 제품 요구사항. 아래 정책 중 원본에 없는 것은 초기 제안이며 구현 시 확정 내용을 기록한다.

제품 목표
호스트가 본인 차량의 정보·사진·가능 일정·요금을 등록하고, 게스트가 주변 차량 검색부터 예약·대여·반납·정산·후기까지 처리하는 차량 공유 앱이다. 공용 기능은 계정, 채팅, 알림, 결제수단, 고객지원이다.

사용자와 권한
- 비회원: 약관·소개·공개 차량 검색/상세/사양만 조회. 정확한 인수 안내 및 사용자 연락처는 공개하지 않는다.
- 계정: 하나의 계정에 게스트/호스트 역할을 추가할 수 있다. 화면 02와 37/47의 역할 전환을 지원한다. 활성 모드 전환과 권한 부여는 구별한다.
- 게스트: 자기 예약·결제·점검·후기·문의에 접근한다. 타인 예약 ID를 알아도 조회/변경할 수 없다.
- 호스트: 자기 차량·가용 일정·예약 요청·수익에 접근한다. 예약 관계가 있는 게스트의 공개 평가만 조회한다.
- 운영자: 손상 검토·인증·분쟁 처리를 위한 서버 권한 확장 지점을 둔다. 원본에 없는 운영자 대시보드 52번 등을 추가하지 않는다. 운영 처리가 미연동이면 확인 대기 상태를 유지한다.

범위와 이동 흐름
- 가입: 00→01→02→03/04→05→06→07→08 또는 25. 비회원은 01에서 08~13의 공개 탐색으로 이동할 수 있다.
- 검색/예약: 08→09/10→11→12→13/14→15↔48→16→17→18. 재방문은 45→18.
- 이용: 18→20→21→22→23→24. 예약 참여자는 19에서 대화하고 44에서 대화 목록을 본다.
- 호스트: 25→26→28→29→30→49→31→32→33↔50→26. 기존 차량 수정은 27→29/30/31/33.
- 관리: 25/34→35↔51, 25/47→36. 공용 37/47→38~43/46, 40→46.
- 이동은 정상 흐름이며 단계 건너뛰기 URL 접근은 서버 상태와 권한으로 검증한다.

예약 상태와 결제 상태 (초기 제안)
REQUESTED: 유효한 계정/본인·면허/동네 인증 및 가용 기간 확인 후 요청 생성. 요청도 동일 기간의 재고를 점유한다. 유효기간 없는 요청은 허용하지 않는다.
APPROVED: 호스트가 요청 승인. 이후 결제 대기 기한까지 재고 점유.
CONFIRMED: 승인된 예약의 결제가 공급자 서버 응답/웹훅으로 검증됨. 결제 버튼 클릭만으로 확정하지 않는다.
IN_USE: CONFIRMED에서 필수 인수 사진·주행거리 제출 후 변경.
RETURNED: IN_USE에서 반납 점검 제출 후 변경.
SETTLEMENT_PENDING: 인수/반납 비교 및 추가 비용 검토 중.
COMPLETED: 합의된 정산 완료. 이때 후기 작성 가능.
REJECTED / CANCELLED / EXPIRED: 허용된 상태에서 거절/취소/기한 만료. 이 상태는 재고를 점유하지 않는다.
- REQUESTED→APPROVED→CONFIRMED를 기본으로 한다. 16의 결제 동작은 요청 시 결제수단 선택/동의, 승인 후 실제 청구로 구현한다. 17은 상태에 따라 '예약 요청 접수'와 '예약 확정'을 구별한다. 원본의 '예약 완료' 표현을 상태 확정으로 오인시키지 않는다.
- 개발 초기 제안: 요청 24시간, 승인 후 결제 30분 이내. 운영 정책 확정 전에는 개발 설정값으로 명시한다. 만료 처리는 재시작 가능한 DB 작업과 요청 시 재검증으로 구현한다.
- 결제 상태: CREATED→PENDING→SUCCEEDED / FAILED, 이후 REFUND_PENDING→REFUNDED / REFUND_FAILED. 지급·환불 실패를 성공으로 기록하지 않는다.
- 취소 시 결제 내역을 삭제하지 않고 환불 거래를 추가한다. 초기 개발 정책은 인수 전 취소 전액 환불, 인수 후 자동 취소 불가이며 실제 운영 정책은 별도 확정한다.
- 공급자 요청에는 예약/거래 기반 멱등키를 사용한다. webhook 중복·역순 수신과 네트워크 시간초과를 처리한다.
- DB 트랜잭션을 열어 둔 채 외부 결제를 기다리지 않는다. 거래를 먼저 저장하고 공급자 확인 후 별도 트랜잭션에서 상태 전이를 검증한다.

가격 계산 (개발 초기 제안)
- 이용일수 = ceil((종료-시작)/24시간), 최소 1일. 종료>시작, 시작은 현재 이후.
- 차량 대여료 R = 일수 × 예약 시점 일일요금, 보험료 I = 일수 × 선택 상품 일요금.
- 게스트 서비스 수수료 G = floor(R×10%), 호스트 중개 수수료 H = floor(R×10%). 서로 다른 수수료이며 화면에서 구별한다.
- 총 예약액 = R+I+G-서버가 검증한 할인액. 초기 할인액은 0이며 원본에 없는 쿠폰 시스템을 추가하지 않는다.
- 호스트 예상 정산액 = R-H. 보험료·게스트 수수료는 호스트 수익에 포함하지 않는다.
- 예: R=68,000, I=18,000이면 G=6,800, 총액=92,800, 호스트 예상=61,200. 보험을 포함하고도 원본처럼 총액을 74,800으로 표시하지 않는다.
- 주행거리 추가료 = max(0,반납계기판-인수계기판-포함거리)×km당 요금. 개발 초기 포함거리=130km/일, 초과=300원/km. 실제 계약값을 예약 시점에 스냅샷 저장한다.
- 통행료는 검증된 내역만 반영한다. AI 손상 후보는 자동 청구하지 않는다. 양 당사자 확인과 운영 검토가 필요한 별도 상태로 둔다.
- 22의 83km와 23의 142km는 서로 다른 시안 예시이므로 실제 예약 하나에서는 같은 점검 데이터를 사용한다.
- 변경된 차량 가격·보험 상품이 기존 예약의 요금 스냅샷을 바꾸지 않는다. 최종액, 수납액, 잔액 및 환불액을 구별한다.

비기능 요구사항
- 서버 입력 검증, 일관된 오류 코드, 페이지네이션, 제한된 업로드, 로그인/인증/문의 rate limit.
- 보안 쿠키 기반 세션 제안: HttpOnly, 운영 Secure, 명시적 SameSite. 서버 세션 만료·로그아웃·세션 폐기 지원. 쿠키 인증의 변경 API는 Origin 검사와 CSRF 방어를 구현한다.
- 비밀번호는 검증된 비밀번호 해시 라이브러리로 처리한다. SQL 직접 문자열 결합 금지. 미등록 개인정보 로그 출력 금지.
- 키보드 사용, 입력 label, 오류 연결, 색만으로 상태를 구별하지 않는 UI. SVG 390×844를 기준으로 좁은 화면과 데스크톱에서도 사용 가능하게 구성한다.
- UTC 저장/Asia/Seoul 표시, 금액 정수, 민감정보 마스킹, request ID와 비밀정보 없는 구조화 로그.
- 실제 동시 요청에서 중복 예약과 결제가 방지되어야 한다. MariaDB 통합 테스트로 검증한다.

출시 전 결정 필요
외부 공급자와 요금·보험 계약, 인증 성공 기준, 위치 인증 경계, 취소/수수료/추가청구 정책, 개인정보 보유 기간, 실제 정산 지급 방식. 구현 중 임의로 실제 연동을 가장하지 말고 adapter 미설정 또는 개발 모드로 구별한다.
