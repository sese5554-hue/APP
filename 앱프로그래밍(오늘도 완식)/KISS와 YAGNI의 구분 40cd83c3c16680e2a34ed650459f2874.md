# KISS와 YAGNI의 구분

<aside>
⚖️

**설계 원칙**

KISS로 핵심 구현은 단순하게 유지하고, YAGNI로 이번에 필요하지 않은 기능은 보류합니다.

</aside>

## 🧩 KISS vs YAGNI 설계 적용표

### 🌿 1. KISS (Keep It Simple · 유지할 조건)

*어려운 구조 대신 단순하고 이해하기 쉬운 구현으로 필수 기능을 완성합니다.*

- **핵심 기능의 직관적 구현:**
    - 식재료 등록 시 '이름', '보관장소(냉장/냉동/실온)', '유통기한' 3개 항목만 탭하여 3초 안에 완료하는 폼 입력 구조.
    - 복잡한 AI 필터링 대신, 식약처 공공 API 호출 시 "유통기한 D-Day가 가장 적게 남은 재료 1개"를 검색 키워드로 전달하는 단순 매칭 방식 적용.
- **최소한의 입력 검증 (Form Validation):**
    - 식재료명 공백 여부 검증 (필수 입력).
    - 유통기한 날짜 선택 검증 (과거 날짜 입력 방지 또는 경고 표시).
- **필요한 데이터만 최소 보존:**
    - MariaDB 테이블에 `id`, `user_id`, `name`, `category`, `expiration_date`, `is_consumed` 등 필수 컬럼 6~7개만 선언하여 데이터 구조 단순화.

### 🚫 2. YAGNI (You Aren’t Gonna Need It · 보류할 예)

*학기 내 완성(14주차) 및 시연(15주차)에 직접적인 영향이 없는 오버 스펙 기능은 모두 보류합니다.*

- **요구가 없는 순위 및 게임화 요소 보류:**
    - 사용자 간 식재료 소진율 랭킹, '식비 절약왕' 배지 시스템, 포인트 적립 기능 등은 이번 구현에서 보류.
- **복잡한 설정 기능 보류:**
    - 알림 수신 시간 세부 지정(아침/점심/저녁 개별 픽커), 테마(다크모드/라이트모드) 세부 변경, 푸시 알림 진동/음향 변경 설정 기능 보류.
- **미래 확장 기능 보류:**
    - 영수증 OCR 카메라 스캔 자동 입력, 식재료 칼로리 및 영양성분 데이터베이스 연동, 이웃 간 식재료 나눔 기능 보류.
