## 🚀 2. 10주차 첫 작업 (Week 10 First Deliverable)

### 🖥️ ① 대상 화면 및 사용자 행동

- **대상 화면:**
    1. **메인 냉장고 목록 화면 (Read):** 냉장 / 냉동 / 실온 3개 탭 구성, 식재료 목록 및 D-Day 표출 화면.
    2. **식재료 3초 등록 바텀시트/폼 화면 (Create):** 식재료명 입력, 보관 장소 선택, 유통기한 날짜 픽커 3개 필드 입력 화면.
- **사용자 행동 흐름:**
    1. 앱 진입 ➔ 등록된 재료가 없을 때 **빈 상태 안내(Empty View)** 확인.
    2. 플로팅 `+` 버튼 클릭 ➔ 식재료 3초 등록 폼 진입.
    3. 식재료명 입력('계란'), 보관 장소 선택('냉장'), 유통기한 날짜 지정 ➔ '저장' 버튼 클릭.
    4. 메인 화면으로 돌아와 해당 탭('냉장') 리스트에 **D-Day 계산 결과**와 함께 카드 추가 확인.

### ✅ ② 검증할 관련 인수 조건 (AC)

- **[AC-01 정상]** 식재료명/보관장소/유통기한 정상 입력 시 해당 탭 리스트에 카드가 즉시 생성되고 D-Day 계산값(`D-N`)이 정확히 노출되는지 확인.
- **[AC-02 입력 오류]** 식재료명을 공백으로 둔 채 저장 클릭 시 경고 스낵바 노출 및 DB 저장 요청이 차단되는지 확인.
- **[AC-04 빈 상태]** 식재료 데이터가 0개일 때 "냉장고가 비어있어요!" 안내 문구와 등록 유도 버튼이 정상 노출되는지 확인.

- **선택 이유:** 식재료 등록(C)과 목록 조회(R)는 모든 기능(D-Day 정렬, 소진 완료, 레시피 추천, 알림)의 기반이 되는 가장 핵심 데이터 흐름이므로 최우선 구현.
