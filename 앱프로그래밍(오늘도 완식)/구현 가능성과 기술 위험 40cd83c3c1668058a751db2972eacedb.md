## 구현 가능성과 기술 위험 분석 명세서

### ⏱️ 1. 시간 & 개발 가능 주차

- **시간:** 10주차부터 14주차까지 총 5주간 구현 (15주차 최종 발표)
- **개발 가능한 주차 및 개인 작업 시간:**
    - **10~14주차 (5주간):** 주당 약 6~10시간 투입 ➔ **총 30~50시간의 개발 타임라인 확보**
    - **15주차:** 발표 자료 작성 및 시연 테스트 진행

### 🧠 2. 기술 & 학습 필요 범위

1. **기술 스택:** Flutter (Client) + Node.js (Express Server) + MariaDB (Database) + AWS Lightsail (Hosting)
2. **배운 내용과 새로 익혀야 할 내용:**
    - **배운 내용 (이미 보유한 기술):** Flutter 기본 위젯, Layout, 화면 이동(`Navigator`), 기초 HTTP 통신 (`http` 패키지)
    - **새로 익혀야 할 내용 (10~14주차 학습):**
        - **[Flutter]** 로컬 푸시 알림 패키지 (`flutter_local_notifications`), 날짜 선택기 (`showDatePicker`), 기본 상태 관리 (`setState` 또는 `Provider`)
        - **[Node.js/DB]** Express REST API 라우팅, MariaDB CRUD SQL 작성, AWS Lightsail 리눅스 인스턴스 환경 세팅

### 🗃️ 3. 데이터 및 저장 방식

1. **데이터 종류:** 사용자 계정, 식재료 데이터 (이름, 보관 장소, 유통기한, D-Day, 소진 여부), 레시피 데이터, 제휴 마케팅 링크
2. **저장 위치 및 유지 필요 여부:**
    - **저장 위치:** AWS Lightsail 내부 MariaDB
    - **유지 필요 여부:** 사용자별 식재료 목록은 앱을 종료해도 영구 보존(Persistent Data)되어야 함

### ⚠️ 4. 외부 의존성 및 리스크 관리

1. **외부 의존 요소:** 공공데이터포털 API, AWS 인프라, 구글/애플 개발자 계정
2. **서버·API·계정·권한·비용:**
    - **서버:** AWS Lightsail 고정 요금제 (월 $3.5~$5)
    - **API:** 식품의약품안전처 '조리식품 레시피 DB' (100% 무료 Open API)
    - **계정/권한:** Google Play ($25, 최초 1회), Apple Developer ($99/년), 모바일 푸시 알림 권한
    - **총비용:** 약 30만 원 예산 범위 이내
3. **대안 (의존성 장애 발생 시):**
    - 레시피 공공 API 서버 장애 시 ➔ 백엔드 MariaDB에 사전 저장해 둔 10가지 자취 시드 데이터(Dummy Recipe)를 반환하는 Fallback 로직 적용.
4. **의존이 어려울 때 유지할 핵심 흐름:**
    - 기기 알림 권한 거부 시 ➔ 앱 메인 화면 상단에 D-3 이하 식재료 시각적 강조 배너(In-App Alert)를 띄워 유통기한 확인 흐름을 유지.
