# 개발환경의 문제점 확인 사항

### ⚡ 1. 앱 속도가 느리거나 답답한 느낌 (네이티브 대비 화면 전환)

- **불편 사항:** 배달의민족, 토스 같은 '네이티브 앱'에 비해 Flutter 앱은 초기 구동(스플래시 화면) 시 아주 미세한 버벅임(Jank)이나 무거운 느낌을 받을 수 있습니다.
- **해결 방향:** 첫 로딩 화면에서 애니메이션을 너무 무겁게 쓰지 않고, 데이터가 로딩 중일 때는 반드시 스켈레톤 UI(반짝이는 회색 틀)나 로딩 인디케이터를 보여주어 앱이 '멈춘 게 아니라 일하는 중'임을 알려야 합니다.

### 📶 2. 네트워크 환경이 조금만 나빠져도 앱이 멈추거나 에러가 뜸 (Node.js 통신 구조)

- **불편 사항:** 사용자가 지하철을 타거나 와이파이가 끊기는 순간, 서버(Node.js)에 요청을 보냈다가 응답을 받지 못해 앱이 무한 로딩에 빠지거나 튕길 수 있습니다.
- **해결 방향:** 앱 내부에서 인터넷 연결 상태를 체크하고, 통신 실패 시 "네트워크 연결이 불안정합니다. 다시 시도해주세요"라는 친절한 안내 팝업을 띄우는 예외 처리(AC)가 필수적입니다.

### 🖥️ 3. 동시 접속자가 조금만 몰려도 앱이 아예 먹통이 됨 (AWS Lightsail 최소 사양)

- **불편 사항:** 월 $3.5~$5짜리 Lightsail 인스턴스는 메모리(RAM)가 512MB~1GB 수준으로 매우 작습니다. 사용자가 한 번에 수십~수백 명만 동시에 몰려도 서버가 뻗어버려 유저는 앱에서 "서버 응답 없음" 오류를 보게 됩니다.
- **해결 방향:** 초기 유저 단계에서는 문제가 없으나, 마케팅을 하거나 유저가 늘어나는 시점에는 Lightsail 사양을 클릭 한 번으로 한 단계 업그레이드하거나 데이터베이스(MariaDB)의 커넥션 풀(Connection Pool) 관리를 효율적으로 해주어야 합니다.

### 🔐 4. 로그인 유지가 안 되어 앱을 켤 때마다 다시 로그인해야 함

- **불편 사항:** 앱을 잠시 껐다 켰는데 세션이 만료되어 매번 아이디와 비밀번호를 다시 입력해야 한다면 유저는 엄청난 피로감을 느낍니다.
- **해결 방향:** Flutter의 로컬 저장소(`flutter_secure_storage` 등)에 토큰(JWT)을 안전하게 저장하고, 앱이 켜질 때 자동으로 로그인을 시도하는 '자동 로그인' 기능이 기획 단계부터 고려되어야 합니다.

### ↩️ 5. 뒤로가기 버튼을 눌렀을 때 앱이 그냥 종료되어 버림 (Android 유저)

- **불편 사항:** 안드로이드 폰 유저들은 하단 내비게이션 바의 '뒤로가기'를 자주 누릅니다. 이때 상세 페이지에서 이전 화면으로 가려고 누른 건데 앱 자체가 완전히 꺼져버리는 조작의 불편함이 자주 발생합니다.
- **해결 방향:** Flutter에서 `PopScope`(구 `WillPopScope`) 위젯을 활용해 뒤로가기 버튼을 눌렀을 때의 행동을 정확히 제어해주어야 합니다.
