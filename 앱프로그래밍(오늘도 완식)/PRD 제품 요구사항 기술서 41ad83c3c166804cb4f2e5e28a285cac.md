## 1. 프로젝트 개요

### 1.1 기본 정보

| **항목** | **내용** |

### 1.2 핵심 가치 제안

번거로운 입력 없이 3초 만에 식재료를 등록하고, 유통기한이 임박한 재료로 바로 해 먹을 수 있는 1인분 레시피까지 추천해 주는 1인 가구 냉장고 관리 앱입니다. 식재료를 다 먹은('완식') 직후에는 제휴 링크를 통해 필요한 재료를 바로 재구매할 수 있도록 연결합니다.

## 2. 기획 배경 및 시장 조사

### 2.1 문제 정의 및 통계 근거

- **식재료 방치 폐기:** 한국농촌경제연구원(KREI) 『식품소비행태조사』에 따르면, 1인 가구 음식물 쓰레기 중 먹고 남은 음식과 상해서 버리는 식재료 비중이 48.2%에 달합니다.
- **유통기한 오인 폐기:** 식품의약품안전처 소비자 인식 조사 기준, 국내 소비자의 56.4%가 실제 섭취 가능 여부와 관계없이 기한이 지나면 식재료를 바로 폐기합니다.
- **배달·외식 의존도 심화:** 서울디지털재단 분석 결과, 1인 가구는 다인 가구 대비 일회용 포장재 배출량이 2.32배 높습니다. 소량 식재료를 관리하고 남은 재료를 활용하기 어렵다 보니 자연스럽게 배달·외식으로 이어지는 구조입니다.

## 4. 개발 범위 및 우선순위

### 4.1 MoSCoW 기준 기능 우선순위

- **Must Have (10~14주차 필수 구현)**
    1. 식재료 3초 등록(Create) 및 입력값 유효성 검증
    2. 보관 장소별(냉장/냉동/실온) 탭 분류 및 D-Day 임박순 목록 조회(Read)
    3. 식재료 완식(소진 완료) 상태 전환(Update) 및 오등록 삭제(Delete)
    4. 유통기한 임박(D-3, D-1) 로컬 푸시 알림 예약 및 취소
    5. 임박 재료 기반 식약처 공공 API 레시피 추천 및 로컬 시드 DB Fallback
    6. 소진 완료 시 쿠팡 파트너스·네이버 쇼핑 재구매 딥링크 연동
- **Won't Have (이번 개발 범위 제외)**
    - 영수증 OCR 카메라 스캔 및 바코드 인식
    - 다중 소셜 로그인(카카오·네이버·구글·애플) 및 다크모드
    - AI 칼로리·영양성분 정밀 분석 및 커뮤니티 게시판
    - 인앱 자체 결제(PG 연동) 및 정기 구독 시스템

### 4.2 KISS / YAGNI 원칙 적용 기준

5주(약 30~50시간) 동안 혼자서 설계부터 배포까지 마쳐야 하므로, 핵심 흐름(등록 → 알림 → 레시피 추천 → 완식 및 재구매)과 직접 관련 없는 부가 기능은 과감히 덜어냈습니다. 기능을 늘리기보다 핵심 시나리오가 오류 없이 매끄럽게 돌아가는 데 집중합니다.

## 5. 상세 기능 명세

- **01 식재료 3초 등록**
    - 메인 화면 우측 하단 플로팅 `+` 버튼을 누르면 바텀시트(Bottom Sheet) 입력 폼이 열립니다.
    - 입력 항목은 **식재료명(Text)**, **보관 장소(냉장/냉동/실온 세그먼트 버튼, 기본값 냉장)**, **유통기한(Date Picker, 기본값 오늘+7일)** 3개로 제한합니다.
    - 식재료명 앞뒤 공백을 제거(`trim()`)한 뒤 빈 문자열이면 저장을 막고 경고 스낵바를 띄웁니다.
- **02 재고 목록 조회 및 D-Day 정렬**
    - 상단 3개 탭(냉장, 냉동, 실온)으로 보관 장소별 재고를 필터링합니다.
    - 각 카드에는 식재료명, 유통기한, 계산된 D-Day 배지(`D-3`, `D-Day`, `D+1` 등)를 표시하며, 유통기한이 임박한 순(`expire_date ASC`)으로 자동 정렬합니다.
- **03식재료 완식 처리 및 삭제**
    - 카드 우측의 '완식' 체크 버튼을 누르면 `is_consumed = true`로 업데이트되어 활성 재고 목록에서 즉시 빠집니다.
    - 잘못 등록한 항목은 카드 좌측 스와이프 또는 상세 버튼을 통해 DB에서 영구 삭제(`DELETE`)할 수 있습니다.
- **04유통기한 임박 로컬 푸시 알림**
    - `flutter_local_notifications` 패키지를 사용해 식재료 등록 시점 기준 **D-3, D-1 오전 10:00**에 로컬 푸시 알림을 예약합니다.
    - 해당 식재료가 완식 처리되거나 삭제되면 예약된 알림 ID를 즉시 취소(`cancel`)해 불필요한 알림이 울리지 않도록 합니다.
- **[F-05] 1인분 맞춤 레시피 추천 및 Fallback**
    - D-3 이하 임박 식재료 이름을 키워드로 Node.js 백엔드에 전달해 식약처 `COOKRCP01` Open API를 호출합니다.
    - 요리명, 대표 이미지, 필요 재료, 조리 순서를 파싱해 추천 화면에 최대 5건까지 보여줍니다.
    - **방어 로직(Fallback):** 외부 API 응답이 2초를 넘기거나 에러가 발생하면, MariaDB `seed_recipes` 테이블에 미리 넣어둔 '자취생 1인분 시드 레시피 10종'을 대신 반환합니다.
- **[F-06] 소진 직후 1클릭 재구매 딥링크**
    - `[F-03]`에서 '완식'을 누른 직후 하단 스낵바 또는 모달 팝업으로 `"[식재료명] 완식! 최저가로 바로 채워둘까요?"` 안내를 띄웁니다.
    - 버튼을 누르면 `url_launcher`를 통해 쿠팡 파트너스 또는 네이버 쇼핑 검색 제휴 링크로 바로 연결합니다.

### 6.2 주요 화면별 핵심 컴포넌트

- **메인 냉장고 화면:** 상단 앱바(서비스 타이틀 + 임박 재료 카운트 배지), 3단 탭바, 식재료 카드 리스트, 하단 배너 광고 영역, 우측 하단 FAB(`+`).
- **식재료 카드:** 좌측 D-Day 상태 배지(긴급/주의/여유 색상 구분), 중앙 식재료명 및 만료일(`YYYY.MM.DD까지`), 우측 '완식' 원형 체크 버튼.
- **3초 입력 바텀시트:** 자동 포커스(`autofocus: true`) 텍스트 필드, 3단 보관 장소 토글 버튼, 원터치 날짜 선택 칩(`+3일`, `+7일`, `+14일`, `직접 선택`), 하단 '등록하기' 버튼.

## 7. 시스템 아키텍처 및 DB·API 설계

### 7.1 전체 시스템 아키텍처

Plaintext

```
[Flutter Mobile App]  <──(HTTPS / REST JSON)──>  [Node.js Express Server (AWS Lightsail)]
- 3초 입력 UI                                     - 입력값 검증 & Parameterized Query
- 로컬 푸시 알림                                  - 식약처 Open API 파싱 & 2초 타임아웃 제어
```

### 7.2 MariaDB 데이터베이스 스키마

**① `users` (사용자 테이블)**

| **컬럼명** | **데이터 타입** | **제약 조건** | **설명** |
| --- | --- | --- | --- |
| `user_id` | INT | PK, AUTO_INCREMENT | 사용자 고유 식별자 |
| `device_uuid` | VARCHAR(64) | UNIQUE, NOT NULL | 기기 기반 경량 사용자 식별 토큰 |

## 8. 예외 처리 및 엣지 케이스

### 8.1 외부 공공 API 지연·장애 시 Fallback 전환 규칙

- **타임아웃 기준:** Express 백엔드에서 식약처 Open API를 호출할 때 `axios` 타임아웃을 2,000ms(2초)로 설정합니다.
- **전환 조건:** ① 2초 초과 타임아웃 발생, ② HTTP 4xx/5xx 에러 응답, ③ 검색 결과(`total_count`)가 0건일 경우 즉시 MariaDB `seed_recipes` 테이블을 조회해 반환합니다.
- **응답 포맷 통일:** API 결과와 Fallback 결과 모두 동일한 JSON 구조(`title`, `ingredients_text`, `instructions`, `image_url`)로 내려주어 앱에서 별도 분기 없이 그대로 렌더링할 수 있게 만듭니다.

### 8.2 유통기한 경과(D+N) 및 당일(D-Day) 표기 기준

- **D+1 이상 (기한 경과):** 진한 회색/검정 배지 (`D+1` 표기, 리스트 최상단에 배치해 폐기나 상태 확인 유도)
- **D-Day ~ D-3 (임박):** 빨간색 강조 배지 (레시피 추천 탭의 필터 키워드로 자동 활성화)
- **D-4 ~ D-7 (주의):** 주황색 배지
- **D-8 이상 (여유):** 초록색 배지

### 8.3 중복 등록·날짜 오류·입력값 필터링

- **동일 식재료 중복 허용:** 1인 가구 특성상 기존에 '계란'이 남아 있어도 새로 산 '계란'을 다른 유통기한으로 따로 등록할 수 있도록 중복 등록을 허용합니다.
- **과거 날짜 선택 방지:** Date Picker의 선택 가능 최소 날짜(`firstDate`)를 오늘(`DateTime.now()`)로 제한해 실수로 이미 지난 날짜를 등록하는 일을 막습니다.
- **특수문자 및 길이 제한:** 식재료명은 최대 20자로 제한하고, 제어 문자나 HTML 태그 기호(`<`, `>`)는 클라이언트와 서버 양쪽에서 걸러냅니다.

## 9. 보안 및 운영·성능 기준

### 9.1 보안 처리

- **민감 정보 분리:** 식약처 Open API 인증키, MariaDB 접속 정보, 쿠팡 파트너스 트래킹 ID는 서버 환경변수(`.env`)로 분리하고 `.gitignore`에 등록해 GitHub 저장소에 올라가지 않도록 관리합니다.
- **SQL Injection 방어:** 백엔드의 모든 MariaDB 쿼리는 문자열 결합 대신 `mysql2` 라이브러리의 Parameterized Query(`?` 바인딩)만 사용합니다.
- **경량 인증 및 소유권 검증:** 이메일·전화번호 같은 불필요한 개인정보는 받지 않고 기기 고유 UUID만 사용합니다. `PATCH`, `DELETE` 요청 시에는 요청자의 `user_id`와 해당 식재료의 소유자 `user_id`가 일치하는지 서버에서 한 번 더 확인합니다.
- **통신 보안 및 CORS:** 배포 서버(AWS Lightsail)에는 HTTPS를 적용하고, Express `helmet` 미들웨어 및 허용된 출처만 접근할 수 있도록 CORS 설정을 적용합니다.

### 9.2 성능 및 운영 기준

- **응답 속도 목표:** 내부 CRUD API는 평균 500ms 이내에 응답하도록 쿼리를 구성하고, 외부 API가 지연되더라도 Fallback 전환을 통해 최대 2.5초 이내에 레시피 화면이 뜨도록 맞춥니다.
- **무중단 프로세스 관리:** AWS Lightsail 서버 내 Express 앱은 `PM2`로 실행해 런타임 에러로 프로세스가 죽더라도 자동 재시작되도록 구성합니다.
- **데이터 백업:** 시연용 초기 데이터와 테이블 구조가 유실되지 않도록 MariaDB 덤프 스크립트(`schema_and_seed.sql`)를 저장소에 함께 관리합니다.

## 10. 수익화 모델

- **핵심 수익원 — 소진 직후 제휴 재구매 (CPS):** 사용자가 식재료 '완식' 버튼을 누르는 순간(재구매 의도가 가장 높은 타이밍) 쿠팡 파트너스 및 네이버 쇼핑 제휴 링크를 띄워 구매 발생 시 수수료(약 3%)를 얻는 구조입니다. 별도 PG 결제 모듈이나 정산 시스템을 구축하지 않고도 트래킹 URL만으로 바로 적용할 수 있습니다.
- **보조 수익원 — 인앱 배너 광고 (CPC/CPM):** 메인 재고 목록 하단 및 빈 화면(Empty View) 영역에 Google AdMob 또는 Kakao AdFit 배너를 배치합니다.
- **향후 확장 방향:** 일정 수준 이상의 사용자 데이터가 쌓이면, 1인 가구의 품목별 평균 소진 주기와 폐기율 통계를 바탕으로 소포장 식품·밀키트 수요 예측 인사이트를 제공하는 방향으로 확장할 수 있습니다.
