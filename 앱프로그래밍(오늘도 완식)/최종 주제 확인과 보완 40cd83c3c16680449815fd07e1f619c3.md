# 최종 주제 확인과 보완

**📌 1. 설명 (Project Overview & Justification)**
• **타겟 사용자:** 식비 절약과 식재료 관리가 필요한 2030 1인 가구 (자취생, 대학생, 사회초년생)
• **핵심 문제:**
    1. 유통기한을 까먹고 방치하다 발생하는 식재료 폐기 및 식비 낭비
    2. 남은 재료 처리 방법 고민으로 인한 메뉴 결정 스트레스
    3. 기존 앱들의 복잡한 입력 UX(영수증 OCR 수정 등)로 인한 지속 사용 실패
• **핵심 흐름:** [3초 식재료 등록] ➔ [D-Day 임박순 남은 목록 확인] ➔ [소진 완료 처리] ➔ [1인분 맞춤 레시피 및 1클릭 재구매]
• **선택 이유:** 5주(30~50시간) 개발 제약 내에서 1인 개발자가 완수할 수 있는 최적의 스코프이며, 15주차 시연 시 식비 절감이라는 명확한 핵심 가치를 시각적으로 증명 가능함.
**🔍 2. 대조 (Alignment Matrix: 기능 - 화면 - 데이터 - AC)구분주요 기능대응 화면관련 데이터 (MariaDB)인수 조건 (AC)등록 (C)**3초 폼 입력식재료 등록 바텀시트`Ingredient` (name, storage_type, expire_date)**AC-01** (정상 등록 및 D-Day 표출)
**AC-02** (공백 입력 검증 및 차단)**조회 (R)**D-Day 정렬 목록메인 화면 (냉장/냉동/실온 탭)`Ingredient` (expire_date, is_consumed)**AC-01** (임박순 정렬)
**AC-04** (0개 시 Empty View 노출)**수정 (U)**소진 완료 처리메인 카드 내 체크 토글`Ingredient` (is_consumed = true)**AC-03** (선택 항목만 목록 제외 및 상태 변경)**연동 (F)**레시피/재구매레시피 추천 탭 및 재구매 팝업`Recipe` (ingredients, external_url)**AC-01** (D-3 이하 재료 키워드 API 매칭)
